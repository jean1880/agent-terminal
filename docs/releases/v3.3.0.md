Agent Terminal 3.3.0 makes Claude, Antigravity and Codex threads look and behave the same: one approval card whose buttons mean the same thing for every agent, one reasoning block, one tool-card grammar, and an approval rule engine that agent-terminal owns for all three agents and that keeps your rules exactly as you write them. Codex can now ask for extra access, show tool-server forms and sign-in links, and share rules with agent-terminal, and replies that end with a choice offer quick replies. It also brings queued prompts, session stability fixes, a Target branch base for the Total Diff viewer, and a redesigned header menu.

## Before you upgrade

- **Approval rules are re-approved.** Rules now live in a new typed, versioned file (`approval-rules.json`). The old `always-allow.json` is ignored and left on disk; approve again what you still want.
- **Rules that earlier versions wrote into a project's `.claude/settings.local.json` are no longer managed.** agent-terminal never writes Claude's settings for "Allow for session" or "Always allow" any more. Clear those entries by hand if you no longer want Claude to auto-approve them outside agent-terminal.

## Added

- [feat] **One approval card for every agent**: Allow once, Allow for session, Always allow, Deny and Stop turn. Deny lets the agent see the refusal and continue; Stop turn ends the turn. A refused card is styled red, never green.
- [feat] **App-owned approval rules**: agent-terminal records every session and always rule itself and answers matching requests for Claude, Antigravity and Codex from one list. Always rules carry the agent they were created on and match across agents by kind (a shell command, one file inside the workspace, or one MCP tool). Session rules end when you switch to another agent, and the switch notice says how many ended.
- [feat] **Reasoning block**: one collapsible block with four states (streaming, complete, replayed, not shared by this model). Claude streams summarised thinking on CLI versions that support it; Antigravity's thoughts are read from its own transcript; Codex shows its reasoning summary.
- [feat] **Queued prompts**: a prompt sent while a turn is running is queued instead of interrupting it. Queued prompts sit pinned at the bottom of the transcript as dashed bubbles and go out in order as each turn ends; Up in an empty composer takes the last queued prompt back for editing.
- [feat] **One tool-card grammar**: `Read <path>`, `Search <pattern>`, `Run <command>`, `Edit <path>`, `Create <path>`, `Fetch <url>`, `<server>/<tool>`, with the raw request behind Details. Codex shell wrappers (`zsh -lc '…'`) are unwrapped.
- [feat] **Copy and Show full** on tool sections, diffs, approval details and errors.
- [feat] **`@` files for Antigravity and Codex** from the app's own index of the thread's folder (secret-looking paths are never listed).
- [feat] **Antigravity hook status** in Settings → Agents: Ready, Not installed, or Could not verify.
- [feat] **Permission sources** in Settings: an optional list of files that import and export read, replacing the built-in path. **View Differences…** lists the rules not yet imported or exported.
- [feat] **Indicator detail**: a command indicator that succeeds now shows its output when clicked (for example a usage figure), not only when it warns.
- [feat] **Unsupported controls explain themselves**: `/help` lists what an agent lacks, and a command it cannot run (for example `/mcp` on Codex) says why instead of being sent as a prompt.
- [feat] **Target Branch Total Diff Viewer**: a `Target branch` comparison base in the right-side diff panel (`Ctrl+Shift+D`) shows every change across all files against the primary branch (`origin/HEAD`, `main`, or `master`).
- [feat] **Animated Header Menu**: an animated hamburger icon replaces the previous plus-menu combination; it rotates to vertical lines when the menu opens and back when it closes, and the menu opens flush below the title bar.
- [feat] **Antigravity Continuation Action**: token-exhaustion and rate-limit detection for Antigravity, offering an immediate continuation into another configured agent.
- [feat] **Codex permission requests**: when Codex asks for extra filesystem or network access, the card says exactly what it asks for (read, write, still blocked, network), with symlinked places shown where they really lead. Allow for this turn or for this Codex session; a session grant is offered only for places Codex cannot rename later, is re-checked on disk the moment you allow it, and never covers the filesystem root, your home folder, Codex's own folder, a project's settings (`.git`, agent instructions) or a file with other names elsewhere. A header chip shows extra access while it lasts. A request agent-terminal cannot describe exactly can only be denied.
- [feat] **Codex tool-server forms and links**: when an MCP server behind Codex asks for details, a form card shows its message as the server's, with typed fields (text, number, yes/no, choices), required marks and inline checks; nothing untouched is sent. A sign-in link card shows the host it opens and warns about local, bare-IP or unencrypted links; nothing opens until you choose Open in Browser. Forms that ask for a password, key or code, oversized forms, and links that are not plain web addresses are declined with a notice.
- [feat] **Codex rules**: Settings → Agents imports Codex's own rules (`~/.codex/rules`) and can export agent-terminal's read-only global rules to `agent-terminal.rules` beside them, each pinned to its system program and checked by Codex's own parser before it is written. Import is all or nothing: if any Codex rule cannot be read safely, nothing is imported and the reason is shown.
- [feat] **Closing screen**: closing a window with agents still running no longer freezes it. The window shows the app icon packing its three dots into the chat bubble, with one line saying what it is waiting on ("Stopping Codex in …", "Codex is not responding, stopping it now…"), and closes as soon as every agent has exited; Quit Now appears if it takes longer. With nothing running, the window closes at once as before.
- [feat] **Codex MCP tool approvals are approval cards**: Codex asks before it runs an MCP tool, and that request now shows as an approval card for `<server>/<tool>`, like Claude's, instead of a form. Your Allow for session and Always allow rules answer it.
- [feat] **Quick replies**: when a Codex or Antigravity reply ends with a question and a short list of choices, the choices appear as quick replies under it; one click puts the answer in the composer, ready to send or edit. Turn them off from the replies themselves or in Settings → General.
- [feat] **Context gauge for Claude and Antigravity**: both report how full their context is only when asked, so the thread now asks after every turn (Codex already reported it unasked).
- [feat] **The rule dialog starts from the bare command and checks as you type**: a rule saved from a Codex `zsh -lc '…'` request is the command itself, so it matches that request next time. An error line under the entry says why a pattern cannot be a rule, and Save stays disabled until it can.
- [feat] **Codex edit approvals show the proposed diff** and name the file, instead of an empty card.

## Changed

- [change] **Your rules mean what you write.** A rule you choose, type or import is kept and matched exactly as written: `git *` covers every git command, `cargo test *` every `cargo test`, and Always allow is offered for any command, edit, read or MCP tool. agent-terminal never refuses or narrows one; when a rule allows more than reading (a program that runs code, an option such as `git -c` or `find -exec`, a `*` on a program that writes, a file outside the workspace or a sensitive one such as `.git`, workflows or `AGENTS.md`), a notice says so when it is kept. Two things no rule can hold: a command with shell syntax (`;`, `&&`, `|`, `$(`, backticks, `$VAR`, redirection, globs, a leading `NAME=value`), which never matches any rule, and a secret, which is never written into one.
- [change] **Allow for session on a read covers the next read.** For a read-only program (`ls`, `cat`, `head`, `grep`, `rg`, `find`, `jq`, `git status`/`log`/`diff`/`show`, …) the button keeps the program for the workspace (`cat …`, `git diff …`), not the one exact command, and the card says so. It covers a read only when its folder and every path it names (arguments, option values such as `--file=…`, and a git `<rev>:<path>`) stay inside the workspace and avoid `.git`, secret-looking files (`.env`, keys, credentials) and home dotfiles, and when it carries no secret and no option that runs code; recursive `grep` and `rg --hidden`/`--no-ignore`/`--follow`/`-u` always ask. What a program picks by itself is not checked: `rg` on a folder reads what it finds (it skips hidden and git-ignored files), and `git diff`/`show`/`log -p` print what git tracks. Other commands keep their exact command.
- [change] **Read options that run programs always ask**: `jq --module-path`, `rg --hostname-bin`, and `git log`/`show` with `--show-signature` or a `%G…` format are never covered by a session read rule.
- [change] **Accept edits chosen during a Codex turn applies from the next turn**; an edit the running turn already asked about still asks.
- [change] **Edits and reads are canonicalised**: a path rule names the file a path really leads to. Antigravity reads outside the workspace now ask in every mode, Plan included.
- [change] **Codex Accept edits** auto-accepts edits inside the workspace while shell commands still ask.
- [change] **Secrets are masked live**, in approval cards, tool cards, questions, notices and prompt snapshots, not only in the store.
- [change] **Import** brings in your Claude, Antigravity, Codex and permission-file rules as written; only an entry carrying a credential or shell syntax is skipped, and the toast says how many. Saving rules is serialised by a lock, so two quick answers no longer race.
- [change] **Export** writes only global rules, escaped, and warns that exported grants live outside agent-terminal.
- [change] **Credentials on the command line** (`curl -u`, `Authorization:` headers, `user:pass@` URLs, password options) are masked in what you see and never become a rule.
- [change] **Compact, continue and fork keep the thread's mode** (and fork its model) instead of adopting the profile default.
- [change] Toasts appear over the transcript and never cover the composer; the header hides its activity text at narrow widths.
- [change] **Usage stays in a narrower header.** As the thread narrows, the header now drops the activity's words before the usage meter (the spinner stays, with the words in its tooltip); the meter goes only with the context gauge.
- [change] **Restart Agent moved to the window menu.** The thread header's reload button is gone, leaving its room to usage and the context gauge. Restarting the agent process on the same conversation is a recovery tool, now last in the ☰ menu as **Restart Agent** (`Ctrl+Shift+R`), which on a chat thread used to do nothing. Stop a running turn with the composer's stop button or `Esc`; its tooltip now carries what stopping does to agents that exit on stop.
- [change] **Header Button Layout**: the quick thread creation button (+) is separate from the main menu, with the menu button first.
- [change] **Branding Consistency**: all user-facing references say "Antigravity" across preferences, menus and status surfaces.
- [change] **Menu Simplification**: duplicate thread creation options are gone from the bottom of the main menu.
- [change] **Clearer thread actions**: "New Thread in Existing Folder…" and "New Thread in Isolated Git Worktree…" (`Ctrl+Shift+G`) replace "New Thread in Folder…" and "New Thread in Worktree…".

- [bug] Codex reasoning summaries no longer show literal `**` markers: reasoning renders as markdown for every agent.
- [bug] Fork attaches its handoff to the new thread rather than whichever thread happened to be selected, and reads the source thread off the main thread.
- [bug] A new Codex thread whose first turn died mid-command can be resumed: its thread is kept from the first item, not only once a turn completes.
- [bug] Stopping or restarting Antigravity while its transcript is being read no longer delivers that stale read.
- [bug] The rule dialog is freed when it closes; its suggestion widgets kept it alive.
- [bug] Settings import and export finish before the toast, the Synced button and the sync indicator report them; permission sources are imported even when no home folder is known; editing permission sources is debounced and their files are checked off the main thread.
- [bug] The diff tool's Command error shows its reason as text instead of parsing it as markup.
- [bug] Adding to a transcript with queued prompts no longer slows down as the thread grows.

## Upgrade and install

Settings and threads are retained; approval rules are not (see above). Download the appropriate package and SHA256SUMS from this release, verify its checksum, then install it:

| Distribution | Command |
|---|---|
| Debian 13, Ubuntu 24.04 or newer | `sudo apt install ./agent-terminal_3.3.0-1_amd64.deb` |
| Fedora 40 or newer | `sudo dnf install ./agent-terminal-3.3.0-1.x86_64.rpm` |
| Arch Linux | `sudo pacman -U ./agent-terminal-3.3.0-1-x86_64.pkg.tar.zst` |
