Agent Terminal 3.0.1 improves chat controls, Codex worker visibility and accessibility, with clearer approvals and useful file-change previews.

## Changed

- Sub-agent details show names, tasks and last reported activity. Active workers are separated from completed and closed workers, so the count reflects current work rather than the entire conversation.
- The chat status distinguishes thinking, running tools, waiting for workers and requests that need your response. Missing telemetry is shown honestly rather than inferred as thinking.
- Expanded header usage shows available usage information across agents, making it easier to choose an agent when switching.
- File-change cards provide meaningful changes through Show changes, with raw tool output available separately.
- Approval cards put Allow and Deny directly within reach; persistent permissions remain separate choices.

## Fixed

- Codex permission controls show the effective mode during a running turn and indicate when a requested mode will take effect on the next turn. Selecting Accept Edits no longer misleadingly suggests that the current turn's policy changed immediately.
- Narrow windows and enlarged chat text retain accessible controls, bounded worker names and usable approval layouts.
- Stopping an agent preserves the draft. Model and effort selection, questions, session controls and sidebar focus behave more consistently.
- Settings validate invalid values inline without overwriting the existing configuration, and completion controls expose clearer accessibility relationships.

## Upgrade and install

Existing settings and threads are retained. Download the appropriate package and SHA256SUMS from this release, verify its checksum, then install it:

| Distribution | Command |
|---|---|
| Debian 13, Ubuntu 24.04 or newer | `sudo apt install ./agent-terminal_3.0.1-1_amd64.deb` |
| Fedora 40 or newer | `sudo dnf install ./agent-terminal-3.0.1-1.x86_64.rpm` |
| Arch Linux | `sudo pacman -U ./agent-terminal-3.0.1-1-x86_64.pkg.tar.zst` |

## Known limitations

- Worker activity and usage depend on information provided by the agent; unavailable values remain explicitly unknown.
- A permission-mode change during a Codex turn takes effect on the next turn. Existing approval requests still require a response.
- Codex session history from its own CLI is not imported yet.
