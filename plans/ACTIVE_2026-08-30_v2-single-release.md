### ⚠ How to actually test a local build (learned the hard way, 2026-08-31)

`adw::Application` uses GApplication single-instance semantics keyed on `APP_ID`.
**Launching a local build while the apt-installed one is running does not run your build** —
GApplication hands the activation to the existing primary instance over D-Bus, which creates
the window in *its* process with *its* environment, and your binary exits 0 immediately.

The journal then shows a plausible-looking successful startup that has nothing to do with your
code. Two WP2/WP3 smoke tests were invalidated this way before the PIDs in `journalctl -o
short-precise` gave it away (log lines attributed to a 14-hour-old `/usr/bin/antigravity-terminal`).

Always run a local build under its own bus:

```bash
dbus-run-session -- ./target/debug/antigravity-terminal
```

Do **not** kill the running instance to work around this — it is the user's live session.
Stub CLIs for exit-path testing live in the session scratchpad (`fakecli/`, `fakecli-clean/`).

### WP1 outcome — what the plan got wrong, and what it found

**D6 (new, 2026-08-31): the pipeline packages with cargo-deb, baked into the build image.**
`cargo-deb` has no apt package on Ubuntu 26.04 (verified: `apt-cache search --names-only cargo`
lists `cargo-auditable`, `cargo-c`, `debcargo`… but no `cargo-deb`), so it is installed with
`cargo install` in `debian-maintainer/Dockerfile`, beside the existing `gem install fpm`. fpm
stays — **eight other packages call it inline** in their own `package_steps`.

Three things the plan did not know:

1. **`-o .` is mandatory, not cosmetic.** `run_build_task` (`debian-maintainer/src/package.rs:1038`)
   collects artifacts with a **non-recursive** `read_dir` of the workspace root. cargo-deb defaults
   to `target/debian/`, so without `-o .` the build fails with "No .deb files generated by build task".
2. **`depends` was double-listing.** `"$auto, libvte-2.91-gtk4-0, libadwaita-1-0"` produced duplicate
   entries where the hand-written half carried no version bound. `$auto` alone derives all of them
   *with* bounds, plus glib/pango/gdk-pixbuf/libc which were never declared.
3. **cargo-deb uses README.md as the extended description** when none is set — the entire document,
   markdown and code fences included, became the control file's Description at 137 lines. Fixed with
   an explicit `extended-description`; control archive dropped 5075 → 694 bytes.

**Verified acceptance** (clean `ubuntu:26.04`, no GNOME): libadwaita absent before install → pulled
in as a dependency; every shared library resolves (`ldd`, no "not found"); icon lands in
`hicolor/scalable/apps` with a basename matching `Icon=`; `desktop-file-validate` passes.
The validator's hint also prompted pairing `TerminalEmulator` with `System` in `Categories`.

### ⚠ Deployment ordering — WP1 is committed but NOT deployed

`debian-maintainer` changes sit on branch `feat/gemini-terminal-cargo-deb`, unmerged. **The order
matters and cannot be varied**, because the middle state is broken either way:

1. **Rebuild the `debian-maintainer` image** so `cargo-deb` exists in it. *(Needs approval — this is
   the live build container.)*
2. Merge `feat/gemini-terminal-cargo-deb` → the pipeline now calls `cargo deb`.
3. Only then merge `release/v2.0.0` → `master` in this repo, which deletes `package.sh`.

Doing 3 before 2 leaves `config.yaml` calling a script that no longer exists. Doing 2 before 1
leaves it calling a binary the image does not have. Until step 1 happens, **do not merge either
branch to master.**

### ⚠ Two findings that reshape the packaging work

**1. `package.sh` is live, not dead.** `debian-maintainer/config.yaml:143-144` has:
```yaml
package_steps:
  - './package.sh {{version}}'
```
The original review called `package.sh` a redundant trap to delete. It is in fact **the path the apt pipeline actually uses** — and `cargo deb` is the one that has never run. Deleting `package.sh` without editing `config.yaml` in the same change **breaks the build pipeline**. WP1 now handles both repos together.

**2. Every package shipped to date under-declares its dependencies.** `package.sh` passes only `-d libvte-2.91-gtk4-0 -d libgtk-4-1`. **`libadwaita-1-0` is missing** — and the app links it and cannot start without it. It works today only because every target machine happens to have libadwaita pulled in by GNOME. On a minimal install, the installed package fails at startup with an unhelpful loader error. `[package.metadata.deb]` in `Cargo.toml` already declares `$auto, libvte-2.91-gtk4-0, libadwaita-1-0` correctly — moving to `cargo deb` fixes this as a side effect.

**3. The pipeline builds every pushed commit** (`follow_releases: false`). So "one release" has a concrete meaning in git terms: **all work lands on `release/v2.0.0` and merges to `master` exactly once.** Intermediate pushes to `master` would each produce an apt package.

# WP2 — Non-UI correctness

No deprecated-API surface, so this is safe to write before the bump.

### 2.1 Move CLI detection off the main thread
`setup_ui` (`imp.rs:352`) calls `detect_cli_binary` synchronously inside a `spawn_local` future — i.e. on the GLib main thread. That runs `which`, then stats, then **`$SHELL -ic "command -v …"`**. A heavy interactive `zsh` freezes the window 1–3 s; Auto mode with nothing installed spawns three interactive shells. The `detected_binary` doc comment claims the cache avoids blocking the UI thread — true for *subsequent* tabs, false for the first detection.

- Wrap the call in `gio::spawn_blocking` and `.await` it inside the existing `spawn_local`. `detect_cli_binary` is already env-injected, so it moves to a worker thread cleanly.
- Delete the `timeout_future(10ms)` frame hack; give the `AdwStatusPage` a real spinner.
- **Make detection application-scoped.** "New Window" calls `app.activate()` and re-runs the whole dance per window. Hoist the result to an app-level cache; window-level `detected_binary` becomes a view onto it.

**Acceptance:** with `sleep 2` at the top of `.zshrc`, the window opens immediately and animates; a second window triggers no detection (one detection round in `journalctl --user -t <identifier>`).

### 2.2 Atomic + debounced config writes
`save_to` (`config.rs:149`) does a bare `fs::write` over the live file — interruption truncates settings. `set_font_scale` (`imp.rs:740`) saves on *every* call, so holding `Ctrl+plus` rewrites the file per key repeat.
- Write to `config.json.tmp` in the same directory → `sync_all()` → `fs::rename`. Atomic within a directory on Linux.
- Coalesce font-scale saves behind a re-armed 500 ms `timeout_add_local_once`; force a save on window close.
- Test: write over an existing file, assert content and no `.tmp` residue.

### 2.3 Remove the dead Startup Script row
`startup_script` is defaulted, persisted, and given a Settings row, while `get_startup_command(binary, _config)` ignores the parameter entirely.
- Delete the row; drop the unused `_config` parameter.
- **Keep the `startup_script` field** with `#[serde(default)]` so existing config files still parse. It returns in WP6 as a per-profile `env_file`, implemented the only way that can work: the existing comment is right that sourcing into the TTY before `exec` breaks Claude's terminal handshake, so the script must be run in a detached subshell and its *exported environment* merged into the env vector `spawn_session` already builds (`imp.rs:777`). It must never touch the TTY.
- Test: a config containing `startup_script` loads without warning.

### 2.4 Retire the loading-screen handler after first fire
`connect_contents_changed` (`imp.rs:766`) fires for the tab's whole life doing a string compare, when its only job is the first transition. Disconnect on first fire via a captured `SignalHandlerId`.

### 2.5 Guard `ThemeChoice::ALL`
`ALL` is hand-maintained and the settings dropdown depends on its ordering in **both** directions (`imp.rs:931` reads by position, `:969` writes by index), untested. A theme added to the enum but not to `ALL` silently mis-maps the dropdown — the user picks "Nord" and gets Gruvbox, with no error anywhere. Add tests: length matches the variant count (via an exhaustive `match` that fails to compile if a variant is added), every variant round-trips index↔value, every `Display` string is unique.

# WP3 — Dependency bump and deprecation sweep (D3)

No user-visible change intended. **Nothing in WP4/WP7/WP8 may be written before this lands.**

### 3.1 Resolve versions empirically
Run `cargo add gtk4@latest libadwaita@latest vte4@latest glib@latest gio@latest gdk4@latest --dry-run`, record what resolves, and check each crate's minimum system GTK/libadwaita. **Do not pin versions from memory.** Neither this box nor the `ubuntu:26.04` build image will be the constraint.

### 3.2 Convert the `clone!` syntax
`glib::clone!(@weak obj => move |…|)` is pre-0.20; current is the attribute form:
```rust
glib::clone!(#[weak] obj, move |…| { … })
glib::clone!(#[weak] obj, #[upgrade_or] glib::Propagation::Proceed, move |…| { … })
```
~20 call sites across `imp.rs` and `main.rs`. **Per the REFACTOR mandate: no `sed` sweep** — the `@default-return` sites and the seven-capture `connect_close_request` block have different shapes and a regex will mangle them. Per-call-site edits, `cargo check` after each file.

### 3.3 Replace deprecated widgets
| Deprecated | Replacement | Sites |
|---|---|---|
| `gtk4::MessageDialog` | `adw::AlertDialog` | `imp.rs:266`, `:287`, `:804` |
| `gtk4::FileChooserNative` | `gtk4::FileDialog` (`select_folder_future`) | `imp.rs:492` |
| `adw::PreferencesWindow` | `adw::PreferencesDialog` | `imp.rs:850` |

Both replacements are future-based, which flattens the current callback nesting — `new_tab_in_folder`'s `run_async` + manual `destroy()` becomes `spawn_local` + `.await`.

### 3.4 Settings becomes apply-on-change (forced by 3.3)
`AdwPreferencesDialog` has **no `connect_close_request`**, and that signal is where all settings currently commit (`imp.rs:950`). Rather than contorting to preserve batch-commit, bind each row's change signal to an `apply_setting` method that mutates config, applies live, and schedules the debounced save from 2.2. This also:
- removes the worst of the "no cancel" problem — nothing commits in one opaque batch at close;
- lets the client/dir-change restart fire from the row that changed, instead of being inferred by diffing at close;
- halves the hand-maintained index↔variant mappings (full removal in WP6).

Add inline validation on Starting Directory: if the expanded path doesn't exist, mark the row `.error` with an explanatory subtitle and don't persist. Today a bad path is accepted, saved, and silently falls back to `$HOME` at spawn with only a `warn!`.

### 3.5 CI
**R1 (see risks):** `ubuntu-latest` may carry older GTK/libadwaita than the bumped crates need — the apt image won't, but CI might. Mitigations in order: pin a newer runner image → add a GNOME backports PPA to the install step → cap the bump. Decide once 3.1 gives real numbers. Keep both clippy jobs until WP8 deletes the feature flag.

**Acceptance:** fmt, both clippy configs, and `xvfb-run -a cargo test --all-targets` green; **zero `deprecated` warnings**; every dialog opens and closes. Run the **rust-reviewer** agent (REFACTOR mandate) — PASS required.

# WP4 — UI correctness

### 4.1 Survive a crashed session — the worst bug in the tree
`wire_tab_signals` (`imp.rs:646`) closes the page on `child_exited` **unconditionally**, and the `n-pages == 0` handler (`imp.rs:429`) then closes the window. If `claude` panics and prints a stack trace, the window vanishes before you can read a character of it.

- Branch on status. **Zero** → close as today (a clean `exit`/`Ctrl-D` should still tidy up). **Non-zero** → keep the page, reveal an `adw::Banner` above the terminal: `Session exited (status N)` + **Restart** / **Close**. The VTE buffer stays intact and scrollable.
- Guard against banner stacking if the replacement dies instantly.
- Distinguish a *launch* failure from a mid-session crash by time-to-exit (~2 s floor) and word it accordingly.

### 4.2 Give `restart_current_tab` an entry point
It already implements the right semantics — open the replacement *before* closing the old page, so the window never drops to zero tabs — and is reachable **only** as a side effect of closing the settings window. Wire a `win.restart-tab` action to: the right-click menu, the 4.1 banner button, and `Ctrl+Shift+R`.

**Acceptance:** with `claude` replaced by a stub that writes to stderr and `exit 1` — the tab stays open, the banner shows status 1, stderr is readable, Restart respawns in the same directory, Close closes the tab. Clean `exit` still closes the tab; closing the last tab still closes the window.

# WP7 — The differentiators

The features a general terminal structurally cannot have. Without these, the app is GNOME Console plus a shell alias — with a splash screen.

### 7.1 Attention when a turn finishes — highest value, smallest change
`adw::TabPage::set_needs_attention()` exists and is **unused**; VTE exposes `connect_bell`.
- Bell in a non-selected tab → `set_needs_attention(true)`; clear on selection.
- Config flag (default off): a `gio::Notification` when a background tab bells, so a finished agent turn reaches you in another workspace.
- Do **not** guess at heuristic "turn complete" detection from output quiescence — ship the bell, see whether it's sufficient in practice.

### 7.2 Scrollback search
10 000 lines of default scrollback with no way to search it. `Ctrl+Shift+F` reveals a `gtk::SearchBar`; wire `search_set_regex` / `search_find_next` / `search_find_previous`. `Enter`/`Shift+Enter` step, `Escape` dismisses, plus case-sensitivity and regex toggles.

### 7.3 Fix the shortcut architecture, then fill the gaps
`Ctrl+Shift+T` is an application accelerator (correct). Copy/paste/zoom live in an `EventControllerKey` attached **to each VTE widget** — so they're inert whenever focus isn't in the terminal, and duplicated per tab.
- Route copy/paste through the existing `win.copy`/`win.paste` actions via `set_accels_for_action`; add `win.zoom-in`/`out`/`reset`. Delete those arms from the key controller.
- Add what has no equivalent today: `Ctrl+Shift+W`, `Ctrl+Tab`/`Ctrl+Shift+Tab`, `Alt+1…9`, plus `Ctrl+Shift+F` (7.2) and `Ctrl+Shift+R` (4.2).

### 7.4 Session restore
`TabState` already holds the `(profile, dir)` tuple you'd serialize.
- Write `session.json` beside `config.json` on window close; restore on launch behind `restore_session` (default **on**) with a "start fresh" override.
- **Cap restored tabs at 20** and treat a parse failure as "start fresh" — a corrupt session file must not spawn unbounded PTYs.

### 7.5 Font family and cursor settings
Font *scale* is a persisted setting with a spin button; the font *family* is a hardcoded const (`imp.rs:588`), as are cursor shape and blink. Add a `gtk::FontDialogButton` for family+size, fold the existing scale into it, and add cursor rows.

# WP8 — Generic status indicators (D2)

### 8.1 Why not just fix the path
`get_drift_status()` (`imp.rs:210`) reads `~/scripts/rag_indexer/drift_report.txt` — **verified absent**. A missing file returns `(false, 0)`, so the header renders the green shield and "System configuration fully synchronized". It is not reporting *clean*, it is reporting *nothing*, dressed as clean — and it's evaluated once at window construction, never refreshed.

### 8.2 Schema and behaviour
```rust
pub struct Indicator {
    pub label: String,
    pub source: IndicatorSource,          // File { path } | Command { argv, timeout_secs }
    pub refresh_secs: Option<u64>,
    pub icon_ok: String, pub icon_warn: String, pub icon_unknown: String,
    pub action: Option<IndicatorAction>,  // ShowOutput | SendToTerminal
}
```
- **Three states, not two.** `unknown` is what a missing file or failed command produces, with its own icon and a "could not read <source>" tooltip. That single change is what fixes 8.1 permanently — the failure mode can no longer masquerade as health.
- Refresh on `refresh_secs` via `timeout_add_local`, not once at construction.
- `Command` sources run through `gio::spawn_blocking` with a timeout — never on the main thread (same lesson as WP2.1).
- **`SendToTerminal` must preview before sending.** Today's "Debug Issue" button calls `feed_child()` with the full report — it types unreviewed file contents into a live agent's stdin. Tolerable as a hardcoded homelab feature; not acceptable as a default affordance on user-configurable sources. Show the text with an explicit **Send** button.
- Cap indicators at 5; truncate tooltips.

### 8.3 Delete the feature flag
Remove `[features]` from `Cargo.toml`, every `#[cfg(feature = "homelab-drift")]`, and the **`Clippy (no default features)`** job from CI. Update `AGENTS.md` — the "put homelab-specific behaviour behind a Cargo feature" mandate is superseded; homelab specifics now live in the user's `config.json`, which honours the standalone philosophy *more* strictly than a `#[cfg]` did.

### 8.4 Re-home the drift indicator
The old source is gone with no obvious successor. Ship a documented `config.json` snippet in `README.md` pointed at something that exists — most likely a small `~/scripts` wrapper around the `ansible_check` MCP tool that writes a report file. **Open item; not a blocker for WP1–WP7.**

## Cross-cutting

### Branching and commits
All work on `release/v2.0.0`, one feature branch per WP merged into it with **`--no-ff`** so each WP stays a bisectable range. Conventional Commits throughout. `release/v2.0.0` → `master` **exactly once** — remember `follow_releases: false` means every push to `master` triggers an apt build. Tag `v2.0.0` at the merge.

### Gate, per work package
`cargo fmt` · `cargo clippy --all-targets -- -D warnings` (plus `--no-default-features` until WP8) · `xvfb-run -a cargo test --all-targets`. The **rust-reviewer** agent must return PASS on WP3, WP6 and WP8 (multi-file Rust refactors — REFACTOR mandate).

### Release-candidate checklist — the cost of a single release
Because there is one verification pass rather than seven, run all of this against the built `.deb` in a **clean `ubuntu:26.04` container with no GNOME session**, before tagging:

1. `dpkg -I` shows `libadwaita-1-0`; install pulls it; app launches (WP1.1).
2. Menu entry renders an icon; `StartupWMClass` groups correctly (WP1.3).
3. Upgrade path: install `1.0.0` from `apt.nuvek.ca` → upgrade → new binary in `/usr/bin`, old gone, **config carried over**, old config file still present (WP5.2, 5.4).
4. Fresh install with no config → defaults; v1.0 config fixture → identical behaviour (WP6.1).
5. Slow `.zshrc` → window paints immediately; second window triggers no detection (WP2.1).
6. Stub CLI exiting 1 → banner, readable stderr, working Restart (WP4.1).
7. Every dialog opens/closes; settings apply live and validate a bad directory (WP3.3, 3.4).
8. Each shortcut in 7.3 fires with focus **outside** the terminal widget.
9. Kill the app mid-write (`kill -9` during a settings change) → config intact, no `.tmp` residue (WP2.2).
10. No indicators configured → clean header; a bogus indicator path → **unknown** icon, not green (WP8.2).

### Rollback
`apt install $NEW=1.0.0` is not available (the package is renamed), so the rollback is `apt install antigravity-terminal=1.0.0` after removing `$NEW`. This works **only because WP5.2 leaves the v1 config in place** — that rule is load-bearing, not politeness. If a regression is found post-tag, revert the `master` merge and let the pipeline rebuild.

### Documentation, in the same release
`README.md` (features, shortcuts, the full `config.json` schema including profiles and indicators, and the migration note), `AGENTS.md` (feature-flag mandate removed; module map updated for profiles), the renamed skill.
