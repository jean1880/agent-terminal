# agent-terminal 3.0 beta audit (2026-10-06)

**Scope:** `feat/v3-chat-first` at `d4aa9697` (beta `gd4aa969`), after the user's first real use.
Four read-only reviews ran in parallel: plan vs implementation, agent-core protocol edge cases,
app side and security (pending), and UI (screenshots of `--chat-demo` plus a code read).
Findings below are as the reviewers reported them; **[verified]** marks the ones I re-checked in
the code, **[live]** the ones the user hit on the beta. Severity: BLOCKER / SHOULD / NICE.

## Fixed during the audit (from live use)

| Item | Fix |
|---|---|
| Sub-agent list rows had no name or description [live] | the explorer now reads the streamed tool input too (`d4aa9697`+1) |
| Thinking bubble made the transcript stutter when the model withheld its reasoning [live] | an empty thinking card takes no space |
| A sent message landed below the fold [live] | sending scrolls to the end; stick-to-bottom re-pins every frame; only real user scrolling lets go |
| Finished sub-agents stayed in the list [live] | the list shows running sub-agents only |

## Ranked findings

### SHOULD (fix before calling 3.0 done)

1. **Structured secrets are stored unmasked** (core S1). `store.rs` `scrub_value` redacts each JSON
   string on its own and drops the key, so `{"api_key": "plain-secret"}` in a tool input or raw
   frame is stored as is. Fix: mask string values under sensitive key names in the Object arm.
2. **Secrets split across streamed deltas are stored unmasked** (core S2). Claude and Codex
   persist per-token `ContentDelta` rows, each scrubbed alone; a token split across two rows
   escapes both. An interrupted turn has no closing snapshot. Fix: scrub the accumulated item text
   at `ItemCompleted` (rewrite the item's delta rows), or keep a tail across deltas.
3. **A `null` field in an agy frame drops the frame** (core S3), so a `result` with
   `"denied_actions": null` never completes the turn (stuck "Working…"). Fix: null-tolerant fields.
4. **Codex: a failed `initialize`/`thread/start` strands a queued prompt** (core S5) as a turn that
   never completes. Fix: fail the queued turn.
5. **Codex ignores `threadId` on notifications** (core S4): a child thread's `turn/completed` could
   end the parent turn. Unverified against a real server (Codex is not logged in here).
6. **Codex usage after a resume counts the whole thread** (core S6).
7. **Claude interrupt during a tool call reads as Completed** (core S7): `terminal_reason:
   aborted_tools` (and interrupt/cancel in `errors[]`) are not treated as interrupted.
8. **Imported tool inputs are unbounded** (core S8): a `Write` with megabytes of content is
   imported whole; the 1500-item cap is not a byte cap.
9. **A tool result made only of images/references shows an empty output** (core S9).
10. **agy `plan_mode: true` in the capability table still says "read-only planning"** (plan),
    contradicting the verified behaviour; nothing in the UI warns at the Plan choice itself.
11. ~~**The agy approval hook is not installed on this PC**~~ (plan): installed and verified via `agent-config` and `agent-sync apply`.
12. **README is behind** (plan): no beta/apt install section; no Codex; GtkSourceView 5.12 missing
    from Prerequisites; Features, Shortcuts and Project Structure are 2.x text.
13. **Question card glyph renders as tofu** (UI 1): its icon is not bundled.
14. **Icon-only buttons have no accessible names** (UI 2): send/stop, jump, gauge, sub-agents,
    copy.
15. **The header does not collapse at narrow widths** (UI 3): chip, mode, activity, sub-agents,
    usage and gauge in one row.
16. **Composer and plan panel are wider than the transcript column** (UI 4).
17. **One Esc interrupts a running turn** (UI 5) — easy to hit while closing typeahead.
18. **Enter accepts the typeahead row** (UI 6): typing `/mod` + Enter completes instead of sending.
19. **`cap_lines` keeps the tail of tool input and raw approval JSON** (UI 7), where the head (the
    command, the path) matters; no "show more".
20. **Approval cards have no keyboard path** (UI 8): no accelerators, focus never moves there.
21. **Low-contrast dim text** (UI 10, 11): usage tags and the placeholder (~3.4:1), the empty-state
    "New Thread" button.

### NICE

- "Always allow" names no scope on the button (UI 9); sub-agent rows only ellipsize the task
  (UI 12); no hover ⋯ on sidebar rows (UI 13); jump button has no unread count (UI 15); no loading
  state for history (UI 16); typeahead popover fixed at 480 px (UI 17); gauge relies on colour
  only (UI 19).
- Core NICE N1–N20: agy custom command without `user_input` opens no turn; stale
  `exit_expected`; Claude `pending` not cleared on a failed result; duplicate `control_request`
  re-emits; `ping` persisted as Unknown; empty `session_id`; stderr lines with "error" become
  banners; Codex id collisions and a dead QUIET entry; unbounded live outputs; redact coverage
  gaps (PASS, PWD, AUTH, COOKIE, DSN; several token prefixes; webhooks; `key : value`; short values);
  a quadratic scan in `redact_after`; `parse_rfc3339` overflow; a mode change restarts Claude and
  Codex though both switch live; catalogue version order with date suffixes; enum forward-compat
  for stored events; `ControlResult.ok: Some(Null)`; import text quirks; handoff header escaping.
- Plan: handoff ignores the target model's window; `thread_read` and `InjectHistory` were dropped
  without recording it; `live_approvals`, `usage` and `questions` caps are not read by the UI; the
  plan still describes the ListView spike and the plan-mode fallback.

## App side and security

### SHOULD

A1. **Import and delete can fail instantly with SQLITE_BUSY_SNAPSHOT** (`store.rs` `import_events`,
    `delete_thread`, `add_dismissed` use DEFERRED transactions that read then write; WAL with a
    second connection writing in between fails at once, busy timeout not applied). A failed import
    leaves the thread blank and, once the session writes its first event, is never retried; a
    failed delete still toasts "Thread deleted". Fix: `BEGIN IMMEDIATE`.
A2. **A transient store failure at thread open re-points the thread at a fresh agent session**
    (`threads.rs` thread build: `store_job` → `None` → `unwrap_or_default()` → no provider → Claude
    gets a new `--session-id` → the native link is overwritten). Fix: refuse to start, offer retry.
A3. **After a package upgrade under a running app, agy runs hookless and the notice says "install
    the hook"**; the real cause (the running binary was replaced) is only logged. Likely with a
    beta that rebuilds on every push. Fix: carry the bind error into the notice ("restart
    agent-terminal").
A4. **Replay keeps the oldest 50,000 events, not the newest** (`threads.rs` `read_history`). A long
    thread opens on its old part. Fix: read the newest window.
A5. **Accept edits auto-allows edits that run code outside the agent**: `.git/hooks/*`,
    `.git/config`, `.envrc` are "inside the workspace"; with a thread in `$HOME`, also
    `~/.bashrc`, autostart and `~/.gemini/config/hooks.json` (the gate itself). Fix: always ask for
    `.git/` paths and known config/dotfiles, and treat `$HOME` (or above) as no workspace.
A6. **Main-thread stalls on the store**: every streamed event is written (and scrubbed) on the main
    connection; a worker holding a write transaction (import, delete) blocks it up to 5 s.
    `create_with_handoff` reads the whole transcript on the main thread. Fix: scrub before BEGIN,
    shorten the worker transactions, move the handoff read off-thread.
A7. **Agents are not stopped when the app quits** (no terminate on shutdown; the SIGKILL fallback is a
    glib timer that never fires once the loop exits; agents are in their own session). Fix:
    terminate all on shutdown with a bounded wait.

### NICE

A-N1 a thread can be opened in two windows (two agents on one native session); open-thread list
is per window. A-N2 the old process's late hook query can satisfy the new one's canary.
A-N3 a deleted cwd gives a cryptic spawn error per prompt. A-N4 a corrupt always-allow file is
overwritten by the next rule (keep a copy). A-N5 tool children inherit the approval socket
variable (forged queries could feed the canary); no line-length cap; stale sockets not swept.
A-N6 relative `XDG_CONFIG_HOME` accepted; config dir 0755. A-N7 checkpoints run repo-configured
clean filters on every turn. A-N8 the external diff tool's temp files are deleted at exit while it
may still be open. A-N9 diff bases and the events table grow without bound.

## Proposed order

1. **Data and safety first:** A1, A2, A5, core S1/S2 (redaction of structured and split
   secrets), A3, A4, core S3 (agy null frames), S7 (Claude aborted_tools), A7.
2. **Robustness:** A6, core S5/S8/S9, Codex S4/S6 (to verify once Codex is logged in).
3. **UI:** question icon, accessible names, narrow header, column widths, Esc/Enter behaviour,
   approval keyboard path, contrast, cap_lines head.
4. **Docs:** README (beta install, Codex, prerequisites, 3.0 features), plan decisions recorded,
   agy `plan_mode` wording.
